# Skill: Slot Generation (BR-01 / BR-02 / BR-03)

## What it teaches
How Miz Ban turns a venue's working hours into bookable slots:
deterministic 90-minute slots with a fixed 30-minute cleaning buffer,
including hours that cross midnight, the ≥24-hour lead rule, and UTC
storage with Jalali only at presentation.

## Steps
1. Slots are generated by `apps/scheduling/services.py` from the venue's
   `OperatingHours` for the requested date — deterministically, from
   open/close times. Venue owners can never edit slot structure.
2. Cycle = 120 minutes: slot `[start, start+90m)`, buffer
   `[start+90m, start+120m)`, next slot starts at `start+120m`. Generate
   while the full 90-minute slot fits inside the working window.
3. Cross-midnight hours (e.g. 18:00–02:00): build the window as datetimes —
   if `close_time <= open_time`, the window ends the next day. Never do
   arithmetic on bare `time` objects across midnight.
4. All computation in aware UTC (`django.utils.timezone`). The date the
   user picked is a Jalali/local date at the API boundary; convert once,
   immediately, via `core/jalali.py`, and keep everything downstream UTC.
5. Bookability filter (BR-03): a slot is bookable only if
   `slot_start_datetime - now >= 24 hours`. Slots inside the window are
   returned as disabled-with-reason, not silently dropped (UX rule).
6. Slot status (free / locked / booked / blocked) is computed at query
   time from bookings + manual blocks — never cached, never stored as a
   generated table that can drift (ARCH-004). Manual blocks
   (`BlockedSlot`) come from the venue owner (FR-011).
7. Working-hours data may be cached (venue metadata, 1h TTL, invalidate on
   edit) — slot *availability* may not.

## Example
```python
# apps/scheduling/services.py — shape of the generator
def generate_slots(open_dt, close_dt):
    """open_dt/close_dt: aware datetimes (close already rolled +1 day if needed)."""
    slots, start = [], open_dt
    while start + timedelta(minutes=90) <= close_dt:
        slots.append(Slot(start=start, end=start + timedelta(minutes=90)))
        start += timedelta(minutes=120)   # 90 slot + 30 buffer (BR-01/BR-02)
    return slots

def is_bookable(slot_start, now):
    return slot_start - now >= timedelta(hours=24)   # BR-03
```

## Common mistakes
- Generating slots from local/Jalali times and storing them (ARCH-006) —
  DST-free Iran time still breaks at date boundaries; UTC is the storage
  and comparison standard.
- Letting the last slot end exactly at close but forgetting its buffer is
  irrelevant — the buffer separates slots, it does not extend the window;
  conversely, don't require buffer after the final slot unless the spec
  says so — follow the design, not taste.
- Off-by-one at the 24h boundary: exactly 24h00m ahead IS bookable
  (`>=`), 23h59m is not. Boundary tests exist for this — keep them exact.
- Pre-generating slot rows for months ahead (they go stale when hours
  change); generate on read, persist only bookings and blocks.
- Using `datetime.now()` naive anywhere in the chain.
